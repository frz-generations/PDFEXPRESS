# Public-sector applicability and evidence crosswalk

**Position date:** 8 November 2026. **Project:** FRZ PDF Express `1.1.0` from the supplied source archive, remediated as a local working copy. **Purpose:** source-based issue spotting for possible institutional review, not a compliance certificate, legal opinion, accessibility audit, cybersecurity audit, or procurement acceptance report.

## Status statement

The supplied archive supports a limited source-code/documentation review and the changes documented in [`REMEDIATION-REPORT.md`](REMEDIATION-REPORT.md). It did not include a government sponsorship/ownership decision, procurement contract, deployed domain or server configuration, production logs, signed installer, STQC certificate, independent security assessment, WCAG/BIS conformance evaluation, screen-reader/user-test report, or departmental acceptance record. This crosswalk therefore reports repository evidence separately from matters that remain unverified. **It does not declare the software compliant or approved.**

Applicability depends on who owns, commissions, controls, operates and hosts a particular service; its users, purpose, data and integrations; and applicable procurement, departmental, state/sector instructions and contracts. A private proposal does not become a government-owned initiative solely because it is intended for review. Conversely, a government-owned or commissioned web initiative may be in GIGW scope. The department must record the scope decision for the concrete deployment. [1]

## Remediation evidence in this source tree

1. `desktop/security.js` implements testable origin, main-frame, permission-context and capability rules; `desktop/main.js` applies them to custom protocol navigation, the PDF tool's privileged IPC, permission checks and requests, and filesystem path resolution.
2. `desktop/test/security.test.js` covers trusted/untrusted origins, spoofed URLs, frame identity, camera-versus-microphone/screen-capture permissions, and fail-closed cases. `tools/check-project.py` tests the 33-tool catalog and selected CSP/inventory invariants.
3. `policies.html`, `NOTICE`, `README.md`, and the Viewer UI accurately disclose local Viewer history, distinguish publisher/institution/host roles, remove fabricated audit claims, and state the current evidence boundary.
4. A pinned Electron desktop dependency lockfile, npm test/audit scripts, an SPDX SBOM, and the existing release workflow's security gates improve reproducibility and traceability while preserving its Linux and Windows output targets.
5. No PDF tool, conversion workflow, branding asset, document-processing library, OCR language data, or product feature was intentionally removed or replaced in this remediation.
