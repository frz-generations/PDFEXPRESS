# Data flow and local retention

**Evidence type:** repository source review of the supplied FRZ PDF Express `1.1.0` archive and remediation copy, as at 8 November 2026. No production traffic capture, host log review, browser profile inspection or legal role determination is included.

## Source-reviewed flow inventory

| Input or data | Client-side path observed | Persistence and deletion | Network/other recipients | Evidence boundary |
|---|---|---|---|---|
| PDFs and images selected in individual tool panels | Browser File/Blob APIs and bundled PDF/image libraries operate in the client. No remote document-processing API or file-upload endpoint was found in the source scan. | Tool-specific processing uses client memory/temporary object URLs; user downloads or prints output. No general document-history store is exposed for these tool panels. | The reviewed app code does not post selected file bytes to a remote processing service. A static-host operator can see ordinary page/asset request metadata, not the in-memory file solely from normal static delivery. | No runtime packet capture with actual files was performed. Do not extend this statement to browser extensions, device backups, host compromise, or operator-added scripts. |
| PDFs opened in the PDF Viewer | Viewer reads selected local PDF files and writes recent-file entries to IndexedDB so they can be reopened. Each entry includes PDF data and metadata. | “Remove” deletes an item; “Clear history” clears the viewer history store. The code attempts to keep at most 30 recent files and about 400 MiB. Storage eviction/quota behavior is controlled by the browser/Electron profile. | Storage stays in the local browser/app profile; the viewer does not upload it. | Deletion is not forensic or backup erasure. Verify the profile and controls on each supported runtime. |
| Scan to PDF camera stream | The scan tool calls browser camera APIs only after the user selects “Start rear camera”; it processes captures in the client. | Captured photos are used in the current scan workflow and output is downloaded. No camera-upload path was found. | No remote camera-processing endpoint was found. The operating system/browser controls the actual camera prompt and device indicators. | Browser/OS permission behavior varies; no platform-permission usability test is included. |
| Preferences and tool settings | Browser local storage is used for theme/viewer and other preferences. | Persists in the site/app origin profile until removed by app/browser data controls. | No account sync service is included in this source. Browser vendor sync or profile backup is outside app control. | Verify exact key/store behavior in the deployed copy and explain it in institutional notices. |
| Offline shell, fonts, OCR data and bundled libraries | Service worker fetches and caches same-origin application resources. OCR and some converters load bundled/same-origin language/font resources. | Static files are stored in the browser Cache API; clearing site data removes them. Viewer file data is a separate IndexedDB store. | The source contains no remote document-processing API, third-party analytics SDK, or externally hosted runtime script. User-activated email/download links may connect to external destinations. `@context` in JSON-LD is metadata, not a runtime fetch by the browser. | Source scanning is not an instrumented browser network trace. A host can inject content or collect access logs unless controlled. |
| Desktop local PDF open/print | Electron main process reads files explicitly selected/opened with the OS and passes data to the local renderer; printing uses OS/local printer integrations. The custom `app://local` protocol resolves packaged local files. | Electron stores Viewer history under the local app profile's origin storage until removed/cleared; the OS/profile may back up data separately. | App assets use the local protocol; print driver and OS interactions are local. | The exact persistence path and signing/update behavior vary by OS/build; inspect the actual package. |
| Device/browser detection and app download links | User-agent/device capability checks are performed by local browser code. | Detection itself is not a server-side account record in the project code. | If the user activates a download or email link, the browser opens its configured external destination. | Destination host and server logs belong to that external operator. |
| Generated outputs | Download APIs create files on the user's device; print integrations use browser/Electron/OS dialogs. | User decides how the output is saved or shared. | The code does not automatically send a generated document to a processing server; an explicit user share/upload action in another app is outside this project's flow. | Review the final content, crop/redaction, metadata and destination before sharing. |

## Privacy and institutional interpretation

Client-side processing is relevant to privacy and security, but it is not by itself a legal exemption. Determine whether inputs, outputs, images, filenames, metadata, usage logs or institutional context identify people; who determines purposes and means; which party operates the device/host; and which retention, records, procurement and sector requirements apply. A department's configured web host, monitoring tools, support workflows, backup policies, browser sync, or later-added scripts can create additional processing not represented by this project archive.

As of 8 November 2026, the DPDP Act's principal processing duties and operational Rules are scheduled for 13 May 2027, with an earlier staged commencement date of 13 November 2026 for specified provisions. This is not a finding that any party is exempt from other currently applicable law, rule, contract or institutional policy. See [`RESEARCH-SOURCES.md`](RESEARCH-SOURCES.md).

## User and operator actions

- Before opening a PDF in the Viewer on a shared device, inform users that Viewer history stores local PDF copies. Provide access to the existing per-item removal and “Clear history” controls.
- Provide a host-specific privacy notice covering access logs, IP/device metadata, retention, support access, backup, breach reporting and contact details.
- Test the deployed browser/Electron profile to confirm the Viewer history entries are actually deleted after each control. Browser/device-level caches, snapshots, backups and media wear are separate.
- Do not add analytics, remote fonts, external scripts, crash uploads or document-handling services without a data-flow review, appropriate authorization and updated user notices.
