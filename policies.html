Accessibility statement

FRZ Generations intends the interface to be usable by people with different access needs. The code includes accessibility-related features such as semantic page structure, some labelled controls, visible focus styling, live status text, and keyboard support for file drop zones. These are feature descriptions, not a conformance finding.

Conformance and evaluation status: no independent accessibility assessment, applicable BIS IS 17802 evaluation, government review, screen-reader test record, or disabled-user test report was included with the supplied source archive. This version does not claim conformance to WCAG 2.1 Level AA, BIS IS 17802, or GIGW 3.0, and does not claim STQC certification or government approval. Automated axe-core and comprehensive keyboard tests are not represented as completed.

The interface is currently in English. PDF page-preview and annotation tasks are visual, and keyboard or assistive-technology support may differ between tools. Do not assume every document or generated output is accessible. The source tree does not establish the status of every workflow at every zoom, screen-reader, or responsive setting.

For an applicable Indian public-sector deployment, the responsible owner should determine scope, arrange qualified manual and assistive-technology evaluation, map findings separately to current GIGW and BIS IS 17802 requirements, test complete tasks with disabled users, and obtain any accessibility review required by procurement or policy. See the scope and evidence crosswalk and dated source notes.

If you encounter an accessibility barrier, write to frzgenerations@gmail.com with the page, tool, steps, browser and assistive technology, if any. Please do not attach a sensitive document unless the maintainers have arranged a secure channel.

Privacy and local storage

  • Document processing: the application source includes no remote document-processing API. Files selected for the tools are handled by the client on the device running the application; the application's normal processing flow does not upload document contents to FRZ Generations. Links that you choose to open, your browser, operating system, or a self-hosting provider may have separate network and logging behavior.
  • Application connections: the supplied project bundles its runtime libraries, fonts and OCR language data. No built-in user-account service, advertising or analytics SDK was found in this source review. User-activated external links (for example, email, issue reporting or a third-party project page) connect to their destination. A self-hosting operator can still receive ordinary web request metadata, such as IP address and requested asset paths, through the hosting stack.
  • Viewer Recent files: PDFs opened in the PDF Viewer are saved by that viewer to the local browser/app profile's IndexedDB so they can be reopened from “Recent files.” The feature attempts to retain at most 30 files and about 400 MiB of PDF data; browser or device storage limits may reduce this. Remove an individual item or use “Clear history” in the viewer. This retention applies to PDFs opened in the viewer, not the separate tools' file picker flow.
  • Other local data: theme/viewer preferences use browser local storage, and the optional offline mode caches application assets in the service-worker cache. These are stored on the device/profile, not sent to a FRZ-hosted account service. Clearing this site's/app's stored data can remove viewer files, preferences and offline assets; browser storage may also be evicted according to browser/device policy.
  • Shared devices: remove PDFs from Recent files and clear the browser/app profile data when appropriate. Removing a Recent-file entry is not a guarantee of secure erasure from operating-system backups, snapshots or storage media.
  • Camera: the phone-scan tool requests camera access only after you choose “Start rear camera” in that tool. Its captured images and output are processed in the client. Your browser or operating system controls permission behavior; review and revoke camera permissions through its settings if needed.
  • Institutional use: local processing alone does not decide whether personal-data law, records policy, retention rules or institutional duties apply. The institution operating or directing the workflow must determine its role, purpose, notices, retention, sharing and applicable legal basis for its actual deployment.

Security

The web application has no FRZ-operated processing backend in this source archive. Its security depends on the delivered code, browser/Electron runtime, hosting and release configuration. A source review, local tests or dependency scan is not a penetration test, code audit, security clearance, or proof that a deployed copy is secure.

For vulnerability reports, email frzgenerations@gmail.com; see security.txt. Describe the affected version, environment, reproducible steps and impact. Avoid sending real personal data or confidential documents. Please allow reasonable time for coordinated remediation before public disclosure.
